# 本地录像管理

停车后，将手机或电脑与设备连接同一 Wi-Fi，在浏览器打开 `http://设备IP:5088`，点击左下角 **录像管理**。也可以直接访问 `http://设备IP:5088/pages/recordings.html`。Dashy 服务需正常运行；如果运行环境缺少 `aiohttp`，应先恢复该服务的依赖。

AGNOS 的系统 Python 环境为只读时，可将可选依赖安装到持久化目录 `/data/python_deps`；启动脚本会将该目录加入 Python 搜索路径，重启后仍可使用，无需写入系统盘。

录像仍使用 openpilot 原有存储目录 `/data/media/0/realdata`，按行程显示录像和日志的总大小、最后记录时间、分段数量及记录状态。页面提供日期/编号搜索、分页和低清道路录像预览。原始 HEVC 录像在导出后使用支持该格式的播放器打开。

## 删除和自动整理

- 勾选行程后点击 **删除所选**，或使用 **选中旧行程** 选择早于 7/30/90 天的旧记录。每批最多 100 个行程，删除前显示数量和预计释放空间并要求确认。
- 删除整段行程时，录像和行车日志一并删除，无法恢复。需要保留的内容应先导出。
- **自动整理** 默认关闭，不改变现有保留习惯。开启后按保留天数或容量上限优先删除最旧的完整行程；默认表单为 7 天、20GB。任一值设为 0 表示取消该项限制。
- 关闭自动整理不会关闭空间不足时的保护：当可用空间小于 5GiB 或 10% 时，原有清理器仍会删除最旧的可删除记录。受保护的事件按原有优先级保留，极端空间压力下仍可能被清理。
- 自动整理的年龄按整个行程的最后一次文件写入时间计算，近期行程、当前记录及正在导出的行程不会按年龄/容量策略删除。boot/crash 不属于该策略。
- 设置和手动删除只能在停车状态下执行。保存后，清理器在下一轮检查（通常不超过 30 秒）应用设置。

## Wi-Fi 导出

点击行程的 **导出 ZIP**，在浏览器下载列表中查看进度。设备须连接 Wi-Fi，保持停车和连接状态。导出包含行程内原始录像和日志，不包含临时锁文件。

ZIP 使用流式传输，不在设备上保存额外的完整压缩包；传输队列固定大小，已压缩的录像不会再次压缩。导出期间持有分段锁，自动与手动清理都不会删除正在导出的文件。完成、取消或连接断开后会释放锁。点火进入行车状态时，正在进行的大文件导出会停止，需停车后重新下载。

## 修复的空间问题

异常退出遗留的 `.lock` 会让旧录像被自动清理器永久跳过。原有锁清理仅在 uploader 启动时执行；关闭 comma Connect 或未注册时，uploader 不运行，旧锁就会积累。

现在清理器独立恢复遗留锁，上传服务也使用同一安全恢复逻辑。仅处理合法的录像分段，跳过当前行程、仍有打开文件的分段、最近 5 分钟写入的文件及符号链接；无法检查进程时保留锁。全部候选都无法删除时，清理器等待下一轮检查，不再每秒重复扫描十次。

这修复了已确认的旧录像无法回收问题。设备报告的 “out of range” 尚未取得对应异常记录，不能据此认定两者是同一个问题。
